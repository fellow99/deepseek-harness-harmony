# 产物解压引导 功能规格

> Module: 004-artifact-bootstrap
> Status: Implemented（首次启动流式解压 dsh-dist.tar.gz → userData/dsh-dist，就位后供 Host 加载）
> Last Updated: 2026-09-04

## 1. 模块概述

### 1.1 目的（Why this module exists）

dsh 部署产物（`dsh-dist/`）在构建期被压缩为单个归档文件随应用分发。本模块在**运行时**负责把这个归档
**解压到应用沙箱可写的数据目录**，使 dsh Host（001-host）随后能从中动态加载其 CLI lib、app-boot 与 profile。

模块的核心价值是「产物就位引导」：把「打包进应用的压缩产物」转化为「运行时可加载的目录树」，并保证这个过程
**幂等**（后续启动不再重复解压）与**可降级**（解压失败不阻塞应用启动）。

### 1.2 解决的问题（What pain points it addresses）

- **打包超限**：dsh 产物包含 5 万+ 小文件，直接打入 HAP 会导致打包阶段卡死/内存爆。压缩为单个归档后，
  应用分发包内只携带一个文件，运行时再还原成目录树。
- **内存溢出（OOM）**：解压后的产物体积很大（约 555MB 量级）。若一次性载入内存再落盘，移动设备（鸿蒙）
  会触发 OOM。因此必须**流式**解压，内存占用与单个归档条目大小成比例，而非与整个产物体积成比例。
- **重复解压浪费**：若每次启动都全量解压，冷启动会被拖慢（首次解压耗时较长）。通过「就位标记」判定产物
  是否已就位，后续启动直接跳过。
- **路径双重前缀**：归档条目自带打包时的目录前缀，解压目标目录本身已含该目录，若不剥离会导致目录嵌套错位。

### 1.3 范围（Scope）

**包含**：

- 归档文件与解压目标目录的定位；
- 就位判定（标记文件是否存在）与幂等跳过；
- 归档的流式解压与逐条目落盘；
- 解压失败/归档缺失的兜底记录（不崩溃）。

**不包含**：

- dsh Host 的启动与加载（见 `001-host`）；
- 窗口创建与 loading 页展示（见 `002-window`，本模块仅在被调用时执行）；
- 应用启动编排（见 `003-lifecycle`，它负责在适当时机调用本模块）；
- 构建期的打包/压缩（见 `005-build-pipeline`，本模块只消费它产出的归档）。

## 2. 用户故事

- 作为用户，我希望首次启动应用时，dsh 产物被自动解压到应用数据目录，无需我手动安装或配置。
- 作为用户，我希望第二次及以后启动应用时，不再重复解压，从而更快进入可用状态。
- 作为用户，我希望即使产物缺失或解压失败，应用也能给出可诊断的错误信息并继续运行（显示兜底页），而不是崩溃退出。
- 作为（宿主/窗口的）开发者，我希望拿到解压后的产物根目录，以便加载 dsh CLI lib、app-boot 与 desktop profile。

## 3. 功能需求

### 3.1 归档与目标定位

- FR-004-001：系统 MUST 定位随应用分发的产物归档（打包进应用的单个压缩归档）。
- FR-004-002：系统 MUST 解析出解压目标目录（应用沙箱可写的用户数据目录下的 `dsh-dist`）。
- FR-004-003：系统 MUST 将解析出的产物根目录暴露给下游模块（供 Host 加载 dsh 产物）。

### 3.2 就位判定与幂等

- FR-004-004：系统 MUST 通过一个就位标记文件判定产物是否已解压就位。
- FR-004-005：当就位标记存在时，系统 MUST 跳过解压并直接返回成功，保证启动幂等。
- FR-004-006：当就位标记不存在时，系统 MUST 执行解压流程。

### 3.3 流式解压

- FR-004-007：系统 MUST 以流式方式解压归档，不得将整个解压后的产物一次性载入内存。
- FR-004-008：系统 MUST 逐条目解析并落盘，正确处理目录条目与普通文件条目。
- FR-004-009：系统 MUST 剥离归档条目中打包时携带的目录前缀，避免解压后出现双重前缀/目录嵌套。
- FR-004-010：系统 MUST 在解压完成后报告实际写入的文件条目数量。

### 3.4 失败兜底

- FR-004-011：当归档文件缺失时，系统 MUST 记录明确的错误并返回失败，不得崩溃。
- FR-004-012：当解压过程发生错误时，系统 MUST 记录错误详情并返回失败，不得阻塞应用启动。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| 归档条目（Archive Entry） | 压缩归档内的单个条目（文件或目录） | 名称、路径前缀、大小、类型标记（目录 / 文件 / 结束块） |
| 产物根目录（DSH_ROOT） | 解压后的 dsh 产物根目录 | 绝对路径（用户数据目录下的 `dsh-dist`） |
| 就位标记（Marker） | 判定产物是否已解压的标记文件 | 绝对路径（产物根目录下某个关键文件的路径），存在即视为已就位 |

## 5. 验收场景

### 场景：首次启动解压

- Given 应用首次启动，产物根目录尚未包含就位标记
- When 调用就位引导流程
- Then 归档被流式解压到目标目录，返回成功，并报告写入的文件条目数量；此后就位标记存在

### 场景：后续启动跳过解压

- Given 产物已解压，就位标记存在
- When 再次调用就位引导流程
- Then 跳过解压，直接返回成功，不产生重复写入

### 场景：归档缺失

- Given 应用分发包内缺失产物归档
- When 调用就位引导流程
- Then 记录「归档缺失」错误，返回失败，应用不崩溃

### 场景：解压过程出错

- Given 归档存在但解压过程发生错误（如损坏、磁盘写入失败）
- When 调用就位引导流程
- Then 记录错误详情，返回失败，应用不崩溃（可继续走兜底页）

## 6. 非功能需求

- **性能**：解压必须流式进行，内存占用与单个条目大小相关，不随产物总体积线性增长（避免移动设备 OOM）。
- **可靠性**：就位引导幂等——同一产物重复调用结果一致，不重复解压。
- **可维护性**：解压逻辑自包含、仅依赖运行时内置能力，不引入第三方解压库。
- **可诊断性**：失败时输出可读的错误信息（含错误详情），便于真机排查。

## 7. 假设与约束

- **假设**：归档采用固定格式（ustar），条目仅含普通文件与目录，不含符号链接、不含 pax 扩展头。
- **约束**：解压目标目录位于应用沙箱可写的用户数据目录内，不触碰沙箱外系统目录。
- **约束（已知代价）**：首次解压耗时较长（产物体积大），期间应用处于初始化等待状态（由窗口模块的 loading 页提示）。
- **约束**：归档条目名称/大小等字段按固定字节偏移解析，与打包格式强耦合；打包格式变更时需同步修改。

## 8. 依赖

**上游（被本模块消费）**：

- `005-build-pipeline`：构建期产出单个压缩归档（dsh-dist.tar.gz）并打入应用分发包，供本模块运行时解压。

**下游（消费本模块）**：

- `001-host`：读取本模块解析出的产物根目录，从中加载 dsh CLI lib、app-boot 与 desktop profile。
- `003-lifecycle`：在应用启动时序中调用本模块的就位引导流程，并依据返回结果决定后续是否启动 Host。
- `002-window`：在首次解压期间展示初始化等待界面（loading 页）。
