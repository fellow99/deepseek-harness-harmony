# 窗口管理 功能规格

> Module: 002-window
> Status: Implemented
> Last Updated: 2026-09-04

## 1. 模块概述

### 1.1 目的（Why this module exists）

负责鸿蒙桌面应用主窗口的创建、加载与兜底：

1. **创建主窗口**——尺寸 1200×800、标题「DSH Desktop」、隐藏菜单栏、显示窗口控制按钮；
2. **分阶段加载**——先显示内联「初始化中」提示页，宿主就绪后同源加载 dsh Web UI；
3. **失败兜底**——宿主未就绪时降级加载空白页，不阻塞应用启动；
4. **渲染进程补丁**——为渲染进程注入随机 UUID 生成能力，补齐鸿蒙 Chromium 缺失的 Web Crypto API；
5. **关窗退出**——关闭全部窗口即退出应用（与生命周期模块协作）。

### 1.2 解决的问题（What pain points it addresses）

- **首装白屏/假死**：首次启动解压 dsh 产物耗时较长（约 45s），期间若直接等待会让用户面对空白窗口。内联 loading 页给出明确「初始化中」提示。
- **Web Crypto 缺失**：鸿蒙 Chromium 的 Web Crypto 可能缺失 `crypto.randomUUID`，依赖该 API 的 dsh Web UI 会报错。每次页面 dom-ready 注入 polyfill 兜底。
- **宿主失败卡死**：宿主启动失败时若无限停留在 loading 页，用户无法感知错误。降级加载空白页并记录错误。
- **冗余菜单栏**：Electron 默认菜单栏在鸿蒙设备上冗余，予以移除。

### 1.3 范围（Scope）

**包含**：

- 主窗口创建（尺寸、标题、菜单栏隐藏、窗口按钮可见性）；
- 加载逻辑（loading 页 → dsh Web UI / 空白兜底页）；
- 渲染进程 `crypto.randomUUID` polyfill 注入；
- 页面加载失败日志记录；
- 窗口重建（应用重新激活且无窗口时）；
- 关窗退出（全部窗口关闭即退出）。

**不包含**：

- 宿主启动与端口（见 `001-host`，本模块只**消费**其 url）；
- 产物解压（见 `004-artifact-bootstrap`，本模块的 loading 页只是覆盖其耗时）；
- loopback 头改写 / HOME 沙箱修正（见 `003-lifecycle`）；
- 窗口控制薄 IPC（最小化/最大化/关闭/状态查询）——本模块未实现（与 desktop 版 002-window 不同）。

## 2. 用户故事

- 作为用户，我希望应用启动时立即看到「初始化中」提示，而不是空白或假死。
- 作为用户，我希望初始化完成后自动进入 DSH Desktop 界面，无需手动操作。
- 作为用户，我希望应用加载失败时给出可诊断的提示，而非静默卡死。
- 作为用户，我希望关闭应用窗口后应用彻底退出，不留后台进程。

## 3. 功能需求

### 3.1 窗口创建

- FR-002-001：系统 MUST 创建主窗口，尺寸 1200×800，标题「DSH Desktop」。
- FR-002-002：系统 MUST 隐藏应用菜单栏并移除默认应用菜单。
- FR-002-003：系统 MUST 启用窗口控制按钮（最小化/最大化/关闭）的可见性。
- FR-002-004：系统 SHOULD 在窗口创建失败时记录错误且不使应用崩溃（不阻塞后续启动流程）。

### 3.2 加载与降级

- FR-002-005：系统 MUST 在宿主就绪前先加载内联「初始化中」提示页（含加载动画与提示文案），避免用户面对空白。
- FR-002-006：系统 MUST 在宿主就绪时，让窗口同源加载宿主提供的 dsh Web UI。
- FR-002-007：系统 MUST 在宿主未就绪（启动失败）时降级加载空白页，不阻塞应用启动。

### 3.3 渲染进程补丁

- FR-002-008：系统 MUST 在每次页面 dom-ready 时，向渲染进程注入 `crypto.randomUUID` 兼容实现（仅当原生 API 缺失时）。

### 3.4 错误与日志

- FR-002-009：系统 MUST 记录页面加载失败（失败 URL、错误码、错误描述），便于诊断。

### 3.5 窗口生命周期

- FR-002-010：系统 MUST 在应用重新激活（activate）且无窗口时重建主窗口并恢复加载。
- FR-002-011：系统 MUST 在全部窗口关闭时退出应用（关窗即退出）。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| 主窗口 | 应用唯一主窗口 | 尺寸 1200×800、标题、隐藏菜单栏、窗口按钮可见 |
| 加载提示页 | 初始化期间显示的内联页面 | 加载动画、标题、提示文案 |
| 渲染进程 polyfill | 注入渲染进程的兼容代码 | `crypto.randomUUID`（getRandomValues 兜底） |

## 5. 验收场景

### 场景：首装初始化提示

- Given 应用首次启动（解压耗时较长）
- When 创建主窗口
- Then 窗口立即显示「DSH Desktop」标题 +「应用初始化中，请稍候…」加载动画

### 场景：初始化完成进入主界面

- Given 宿主已就绪并返回 url
- When 解压与宿主启动完成
- Then 窗口加载宿主提供的 dsh Web UI（同源）

### 场景：宿主启动失败降级

- Given 宿主启动失败（返回 null）
- When 加载主界面
- Then 窗口加载空白页，应用不崩溃，并记录错误日志

### 场景：关窗退出

- Given 应用运行中
- When 关闭全部窗口
- Then 应用退出

### 场景：加载失败记录

- Given 页面加载失败
- When 加载失败事件触发
- Then 记录失败 URL、错误码与错误描述

## 6. 非功能需求

- **性能**：窗口创建后立即显示轻量内联 loading 页（首帧即出），不阻塞；加载完成后切换，无额外轮询。
- **可靠性**：宿主失败/窗口创建失败均有兜底，不静默卡死、不崩溃。
- **可维护性**：loading 页、polyfill、窗口逻辑集中在主进程入口，便于审计。
- **可诊断性**：加载失败、窗口创建失败均记录日志，支持真机排查。

## 7. 假设与约束

- **假设**：加载失败/宿主失败时兜底空白页即可接受（MVP 不做错误详情 UI）。
- **假设**：宿主就绪后窗口直接切换加载，loading 页已覆盖等待期，无需「就绪后再显示」等显隐控制。
- **约束**：关窗即退出——窗口关闭后由生命周期模块的 `window-all-closed` 触发应用退出。
- **约束**：主窗口固定 1200×800，不提供用户可调尺寸（MVP）。

## 8. 依赖

**上游（被本模块消费）**：

- `001-host`：提供宿主 url（宿主为 null 时本模块走降级路径）。
- `004-artifact-bootstrap`：首装解压 dsh 产物，本模块 loading 页覆盖其耗时。
- `003-lifecycle`：关窗退出（`window-all-closed` → 应用退出）、loopback 头改写、HOME 沙箱修正——本模块只在其框架内建窗/加载。

**下游（消费本模块）**：

- 渲染进程（dsh Web UI）：被本模块加载，接受注入的 polyfill。
