# Web 桥接层 功能规格

> Module: 008-web-bridge
> Status: Implemented
> Last Updated: 2026-09-04

## 1. 模块概述

### 1.1 目的（Why this module exists）

本模块是 Electron 宿主（Node.js 侧）与鸿蒙设备系统能力之间的**桥接层**（copy 自 `harmonypc-electron` 运行时，`web_engine` HAR）。它让一个「Electron 主进程 + 渲染进程」的桌面应用能跑在鸿蒙设备上：

1. **承载窗口渲染**——用一个可渲染的视图面承载 BrowserWindow 的渲染输出，让 Electron 窗口在鸿蒙 UI 中可见、可交互；
2. **暴露系统能力**——把鸿蒙的通知、剪贴板、权限、窗口、文件、设备、媒体等系统能力，以「可由宿主侧调用」的方式暴露给 Electron Node 侧；
3. **承载运行产物**——把 Electron 运行所需的资源（Chromium 资源、dsh 产物、主进程入口）打包进应用，供运行时加载；
4. **生命周期编排**——管理 Ability 生命周期、跨设备接续、系统分享、应用退出（含托盘退出协商）。

### 1.2 解决的问题（What pain points it addresses）

- **Electron 与鸿蒙的能力断层**：Electron 应用依赖的 `Notification`/`clipboard`/`BrowserWindow` 等桌面能力，在鸿蒙上没有原生对应物。本模块把鸿蒙系统能力翻译成宿主可调用的方法。
- **窗口渲染承载**：Electron 的 Chromium 渲染输出需要落地到鸿蒙的 UI 树上，本模块提供视图承载与手势/拖拽/输入事件转发。
- **产物与资源打包**：Electron 运行时依赖大量 Chromium 资源文件与 dsh 产物，本模块的 `resfile` 目录是它们的固定承载位置。

### 1.3 范围（Scope）

**包含**：

- 窗口承载视图（承载 BrowserWindow 渲染 + 手势/拖拽/输入转发）；
- 系统能力桥接（通知/剪贴板/权限/窗口/文件/设备/媒体/打印/截图/分享等约 40 组能力，以「能力适配 + 方法注册」成对出现）；
- Ability 生命周期管理（创建/销毁/接续/分享/退出协商）；
- 权限声明（约 28 项运行时权限 + 1 项自定义内核权限）；
- 运行产物承载（`resfile` 承载 Chromium 资源 + dsh 产物 + 主进程入口）。

**不包含**：

- Electron 原生运行时本身（`libelectron.so` 等 SO，属 `007-runtime-entry`）；
- 主进程编排逻辑（`runProfile` / `loadURL` / Host 启动，属 `001-host`、`002-window`、`003-lifecycle`）；
- dsh 产物构建与收集（属 `005-build-pipeline`）；
- 独立浏览器 demo 应用（`chromium` 模块，已裁剪，见 docs/工程规划.md §16）。

## 2. 用户故事

- 作为 Electron 应用开发者，我希望在鸿蒙设备上创建的窗口能被鸿蒙 UI 承载显示，用户可正常交互。
- 作为 Electron 应用开发者，我希望在鸿蒙设备上调用通知、剪贴板、权限等桌面能力时，能被映射到对应的鸿蒙系统能力。
- 作为用户，我希望点击通知、关闭窗口、调整窗口尺寸等系统交互能正确回传给应用。
- 作为应用，我希望在系统发起应用终止时，有机会协商（如托盘退出），而非被强制终止。

## 3. 功能需求

### 3.1 桥接方法注册

- FR-008-001：系统 MUST 在应用启动早期（Ability 阶段）完成桥接方法注册，使宿主侧能调用已暴露的鸿蒙能力。
- FR-008-002：系统 MUST 以「能力适配单元 + 方法注册」成对的方式组织桥接——每个系统能力由一组成对的适配实现与注册入口构成。
- FR-008-003：系统 MUST 支持约 40 组系统能力的桥接注册，覆盖窗口、通知、剪贴板、权限、文件、设备、媒体、打印、截图、分享、蓝牙、定位、输入法等类别。
- FR-008-004：系统 MUST 在注册前完成原生上下文初始化，保证注册方法绑定到正确的进程上下文。

### 3.2 窗口承载

- FR-008-005：系统 MUST 提供一个可渲染的视图面承载 Electron 窗口的渲染输出。
- FR-008-006：系统 MUST 在视图就绪时启动浏览器渲染，并把初始加载地址交给宿主。
- FR-008-007：系统 MUST 转发系统窗口事件（尺寸/位置/状态/可见性/键盘高度/显示切换等）给宿主，供其同步窗口状态。
- FR-008-008：系统 MUST 支持多窗口能力（主窗口、子窗口、嵌入式窗口），并按窗口标识区分。
- FR-008-009：系统 MUST 支持拖拽、双指缩放、平移等手势/输入事件的采集与转发。

### 3.3 系统能力桥接

- FR-008-010：系统 MUST 暴露通知能力——发送通知、关闭通知、查询活跃通知、申请通知权限、查询通知开关状态，并把通知点击/关闭/按钮点击事件回传给宿主。
- FR-008-011：系统 MUST 暴露剪贴板能力——写入/读取文本、HTML、图片、URI、自定义格式数据，并支持查询指定 MIME 类型是否存在。
- FR-008-012：系统 MUST 暴露权限能力——按能力类型（定位/麦克风/相机/截图/剪贴板/蓝牙/目录/屏幕录制/分布式数据同步）申请与检查权限，并支持文件访问权限的持久化与激活。
- FR-008-013：系统 MUST 暴露窗口管理能力——创建/关闭窗口、最大化/最小化/还原、设置位置/尺寸/标题/置顶/全屏/模态/焦点/缩放比例/尺寸上下限、移动/缩放开关、按坐标查窗口、隐私模式、阴影、快速登录等。
- FR-008-014：系统 MUST 在宿主请求的系统能力超出当前支持范围时，返回明确的失败结果而非静默失败。

### 3.4 生命周期管理

- FR-008-015：系统 MUST 在应用终止前与宿主协商（如托盘退出请求），给宿主机会阻止退出或允许退出；协商超时或未决时按「取消」处理。
- FR-008-016：系统 MUST 支持跨设备接续（continuation）——接续启动时恢复窗口内容，避免窗口挂起。
- FR-008-017：系统 MUST 支持系统分享数据的接收，并把分享记录规范化后回传给宿主。
- FR-008-018：系统 MUST 支持重复启动的实例路由（通过实例键或最近活跃窗口标识决定归属窗口）。

### 3.5 权限声明

- FR-008-019：系统 MUST 声明运行时所需的系统权限（约 28 项），覆盖网络、浮窗、剪贴板、麦克风、相机、定位、蓝牙、目录读写、屏幕录制、传感器等。
- FR-008-020：系统 MUST 声明自定义内核权限（可写代码内存）以支持运行时动态代码能力。

### 3.6 运行产物承载

- FR-008-021：系统 MUST 提供固定目录承载 Electron 运行所需的 Chromium 资源与 dsh 产物（主进程入口 + 产物归档）。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| 原生上下文 | 桥接层与原生运行时交互的入口，承载方法绑定与窗口回调 | 进程上下文类型、方法绑定、窗口回调、命令执行 |
| 桥接方法 | 注册给宿主侧调用的方法 | 方法名、方法实现、所属能力类别 |
| 能力适配单元 | 某一类鸿蒙系统能力的实现（通知/剪贴板/权限/窗口等） | 初始化/反初始化、能力方法 |
| 注册入口 | 把适配单元的方法注册到原生上下文的入口 | 绑定方法名清单 |
| 窗口 | 承载渲染的窗口单元 | 窗口标识、启动地址、窗口偏好（隐藏标题栏/可最大化/可最小化/可关闭） |
| 运行产物目录 | Electron 资源与 dsh 产物的承载目录 | Chromium 资源、主进程入口、产物归档 |

## 5. 验收场景

### 场景：桥接方法注册

- Given 应用启动，进入 Ability 阶段
- When 初始化原生上下文并执行注册
- Then 宿主侧能通过注册的方法名调用到对应的鸿蒙能力

### 场景：窗口承载与事件转发

- Given Electron 应用请求创建窗口
- When 视图面就绪并启动浏览器渲染
- Then 渲染输出显示在鸿蒙窗口内，窗口尺寸/位置/状态变化能回传给宿主

### 场景：通知桥接

- Given 宿主请求发送通知
- When 通过桥接方法调用通知能力
- Then 鸿蒙系统发布通知；用户点击/关闭通知时事件回传给宿主

### 场景：剪贴板桥接

- Given 宿主请求写入/读取剪贴板
- When 通过桥接方法调用剪贴板能力
- Then 文本/HTML/图片/URI 数据在系统剪贴板与宿主之间正确传递

### 场景：权限申请

- Given 宿主请求某能力（如相机）
- When 通过桥接方法申请对应权限
- Then 系统弹出授权，结果以授权状态回传给宿主

### 场景：退出协商

- Given 系统发起应用终止
- When 桥接层向宿主发出退出请求
- Then 宿主可阻止（取消终止）或允许（继续退出）；超时按取消处理

## 6. 非功能需求

- **可维护性**：能力适配单元与注册入口成对组织，依赖注入解耦，新增能力时无需改动既有能力。
- **健壮性**：能力调用失败（权限未授权、上下文缺失、API 版本不足）均记录日志并返回明确结果，不崩溃。
- **版本兼容**：按设备 SDK API 版本做能力降级（如 API 15/20/21/22 分支），不因单点新能力导致旧设备不可用。
- **可诊断性**：统一日志前缀与 TAG，便于真机 hilog 排查。

## 7. 假设与约束

- **假设**：本模块为「集成面级别」桥接层——系统能力实现（约 46 个适配单元）与注册入口（约 40 组）直接来自运行时，本工程只做接线复用，不新造能力。
- **假设**：设备形态为 2in1 / tablet（对齐运行时的 `deviceTypes`），手机形态差异不在本模块覆盖。
- **约束**：桥接依赖原生运行时（`libadapter.so` 等）已编译好，本模块不参与原生编译。
- **约束**：权限声明集中在桥接模块的模块清单内（而非入口模块）。

## 8. 依赖

**上游（被本模块消费）**：

- `007-runtime-entry`：提供 Electron-on-鸿蒙原生运行时（SO）与启动流程，本模块作为其 HAR 依赖被引用。
- 原生桥接运行时（aki / adapter / addon 三件套）：提供方法注册与类型桥接能力。

**下游（消费本模块）**：

- Electron 主进程（Node.js 侧）：通过 addon `require()` 调用本模块注册的桥接方法。
- 渲染进程：其渲染输出被本模块的视图面承载显示。
- `001-host` / `002-window` / `003-lifecycle`：主进程编排通过桥接方法触发通知、窗口等能力。
