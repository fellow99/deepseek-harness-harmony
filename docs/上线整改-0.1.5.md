## 2. 逐条问题分析与整改

### 2.1 内部规则 问题 1 — 渲染打开网页未使用 ArkWeb 组件

> 专项分析与设计（现状证据 / 方案 A·B·C 对比 / PoC 计划 / 决策点 / 复审口径）：见 [`N1-ArkWeb合规-分析与设计.md`](./N1-ArkWeb合规-分析与设计.md)。

**状态：方案 A 已实施（2026-09-24）**
1. ✅ `EntryAbility.skills` 移除 `entity.system.browsable` 与 `ohos.want.action.viewData`（应用不再是 URL 处理目标，不再是「浏览器」）；源 + `runtime-overlays` 镜像一致，已入 `OVERLAY_FILES`。
2. ✅ 新增 **ArkWeb** 页 `electron/src/main/ets/pages/ExternalWeb.ets`（外部网页统一由其渲染；空 URL 兜底提示），并登记 `main_pages.json`（源+镜像，`main_pages.json` 已入 `OVERLAY_FILES`；`ExternalWeb.ets` 已入 `OVERLAY_ADD_FILES`）。
3. ✅ `src-main/main.js` 安装**外部网页拦截**：`setWindowOpenHandler` 拒绝弹窗、`will-navigate` 拒绝非本应用来源导航（Chromium 不再用于打开网页）。
4. ⏳ 待启动：方案 B 的 **PoC**（ArkWeb 能否跑通 dsh UI）；复审口径见设计文档 §8。
5. ⏳ PoC **已搭建**（旁路式，不影响正常启动）：`ArkWebProbeAbility` + `pages/ArkWebProbe`（ArkWeb + 文档起始注入 + 结构化探测）、`DSH_ARKWEB_PROBE=1` 打印认证 URL；已入 overlay 守卫（`OVERLAY_ADD_FILES` 5→7）。**设备（2in1）回归后按设计文档 §6.1 执行实测**；PoC 资产**上架前必须移除**。

**审核原文**
> 经检测发现，应用渲染打开网页时，未使用 ArkWeb 组件，不符合应用市场审核标准。请参考 web-component-overview 接入。

**根因（已定位，证据充分）**

- 主界面并非 ArkWeb 渲染：主进程 `src-main/main.js` 用 Electron `BrowserWindow.loadURL(host.url)` 加载 dsh Web UI；鸿蒙侧 `web_engine/src/main/ets/components/WebWindow.ets` 以 `XComponent(SURFACE)` + `nativeContext.runBrowser(args)` 把 **原生 Chromium 渲染面**贴进窗口。即：**渲染引擎是随包分发的 Chromium，不是 ArkWeb**。
- 全仓 ArkWeb 仅两处：`NativeMessagingAdapter.ets`（原生消息，非页面渲染）、`electron/src/main/ets/pages/WebPage.ets`（华为账号认证协议演示页，未接入 dsh 主流程）。
- 佐证「应用被视为浏览器语义」：`electron/src/main/module.json5` 的 `EntryAbility.skills` 同时声明 `entity.system.home` + **`entity.system.browsable`** 与 **`ohos.want.action.viewData`**，会被系统当作可处理 `viewData`（打开 URL）的目标。

**为何是硬阻塞**：华为对「渲染网页」的应用强制要求 ArkWeb；本应用 UI 即 HTML/JS（dsh Web UI），且带 browsable 语义，检测/人工审核都会命中。

**整改方案（分两档，建议 A 先落地、B 做 PoC 决策）**

**A. 立即可做（必做，本批次）**
1. **消除浏览器语义**：从 `EntryAbility.skills` 移除 `entity.system.browsable` 与 `ohos.want.action.viewData`（除非确有「打开外部 URL」的产品诉求）；`BrowserAbility`/`StatelessAbility` 若非必要一并评估裁剪。产出物：`electron/src/main/module.json5` + 对应 `runtime-overlays/electron/src/main/module.json5`（两处同步，否则 stage ⓪ 覆盖回滚）。
2. **所有「外部网页」统一走 ArkWeb**：新增 `pages/ExternalWeb.ets`（`@kit.ArkWeb` 的 `Web` 组件 + 地址栏/返回 + `onLoadIntercept`），凡应用内需要打开 http/https（帮助、文档、隐私政策、用户协议、外链）一律指向该页；禁止用 `about:blank` 或空 URL 打开。
3. **回复审核口径**：说明主界面为**应用自带界面**（本地进程内 dsh Host 同源提供，非浏览器上网），并已按 A 项完成外链 ArkWeb 化。（模板见 §7）

**B. 若审核坚持「主 UI 也必须 ArkWeb」（推荐做可行性 PoC，再决策）**
- 保留 Electron 主进程（Node）承载 dsh Host 不变；**把渲染层由 Chromium 换成 ArkUI `Web` 组件**加载同一同源地址（`http://<LAN IP>:<port>/`）。
- 需解决：
  - `preload`（`src-main/renderer-preload.js`：`crypto.randomUUID` polyfill + `__DSH_TRANSPORT__.ownsHost`）改由 ArkWeb `javaScriptProxy` / 注入脚本在文档开始前注入；
  - `nodeIntegration/contextIsolation` 相关耦合排查（dsh Web UI 是否依赖 Node 能力）；
  - dsh `WebApiClient` 的 `fetch` + WebSocket 在 ArkWeb 内核下的行为验证；
  - 输入法/拖拽/剪贴板/缩放等 `MultiInputAdapter`/`DragDropAdapter` 交互回归。
- 风险：工作量与不确定性大（渲染层重写），且与「Electron-on-鸿蒙」方案假设冲突；**建议先以最小 PoC 验证「ArkWeb 能完整跑通 dsh Web UI」再决定是否切换**。

**验收标准**
- 全仓 `ArkWeb` 检索：所有对外 URL 打开路径均经 `pages/ExternalWeb.ets`；
- `module.json5` 无 `browsable` / `viewData`（或已确认保留理由）；
- 若走 B：设备上 ArkWeb 加载 dsh Web UI，新建会话/发消息/工具调用/设置页均正常；
- 复审回复已提交（§7）。

### 2.4 应用功能 问题 1 — 隐私弹窗「用户协议」打开空白

**审核原文**
> 测试步骤：隐私弹窗-用户协议，打开显示空白。

**根因分析（多因排查；仓库内**无**自实现隐私页，须真机复现定位）**

| 假设 | 证据 / 推理 | 判定方法 |
|---|---|---|
| H1 华为账号协议演示件的 `AgreementDialog` 空白 | `QuickLoginButtonComponent.ets` 的 `AgreementDialog` 中，《用户服务协议》《隐私协议》两个 `Span` **未绑定跳转逻辑**（仅 `USER_AUTHENTICATION_TAG` 触发）；且 `WebPage.ets` 以 `params.url ?? ''` 取值，**url 为空时 ArkWeb `Web(src:'')` 即空白** | 真机走登录/协议入口复现；抓 `hilog` 的 `click privacy text tag` 日志 |
| H2 系统隐私弹窗的协议链接指向空 | 应用无隐私政策配置（仓库无 html/rawfile 协议页）；AGC 隐私声明未配置或指向占位地址 → 系统弹窗「用户协议」打开空白 | 检查 AGC「隐私声明」配置；真机首启观察弹窗来源 |
| H3 空 URL 导航 | 任何以 `router.pushUrl({url:'pages/WebPage', params:{url:''}})` 或空 `src` 打开 ArkWeb 的路径 | 全仓检索 `pages/WebPage` 调用点与 `Web({src` |
